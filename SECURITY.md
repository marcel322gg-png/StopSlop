# Security Policy

## Project status

StopSlop is under active development and is not a finished consumer release. No stable release series is currently designated as security-supported.

## Reporting a vulnerability

Do not publish exploitable vulnerabilities, credentials, access tokens, private TikTok data, or unredacted logs in a public GitHub issue.

Use GitHub's **Private vulnerability reporting** feature on the StopSlop repository when it is enabled. Repository maintainers should enable this feature before inviting public security testing. If private reporting is unavailable, do not post exploit details publicly; contact the repository owner through a private contact channel listed on their GitHub profile and ask for a secure reporting route.

Include the affected commit or release, component, impact, reproduction conditions, and a proposed mitigation when safe to do so. Redact personal data and secrets.

## Scope and limitations

The project has not undergone an independent security audit. A successful build or a manual functional check is not a security certification. Reports concerning Morphe, HushFeed-derived code, TikTok, Android, or third-party dependencies should identify the affected upstream component when known.
